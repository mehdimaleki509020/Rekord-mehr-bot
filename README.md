# رکورد غیربرقی مهر

ربات بله برای دریافت فایل خام SalesReport، نمایش هدف و پاداش 92 فروشنده، گزارش گروه و رتبه‌بندی.

## وضعیت نسخه 2.2

کد و آزمون‌ها آماده‌اند. استقرار و آزمون زنده بله هنوز انجام نشده است؛ دسترسی حساب Cloudflare باید برقرار شود. اتصال GitHub به‌تنهایی دسترسی Cloudflare را فراهم نمی‌کند.

## داده و فرمان‌ها

- فایل XLSB خام تا 20MB با پردازش تدریجی؛ XLSX / XLS / CSV برای فایل‌های کوچک تا 2MB. بارگذاری فقط توسط مدیرهای مشخص‌شده.
- ستون‌ها: `سال`، `شماره ماه`، `روز`، `PH11`، `مشاور فروش`، `نام فروشگاه`، `مبلغ کل صحیح`.
- دوره پیش‌فرض: مهر 1405؛ کتگوری `خانگی غیر برقی`؛ مبالغ ریال به میلیون تومان تبدیل می‌شوند.
- گزارش باید تجمعی و شامل همه شعب مشمول باشد. نبودن فروشنده در فایل کامل به معنی فروش صفر است.
- نام فروشندگان با اصلاح حروف عربی/فارسی، فاصله، تکرار و جابه‌جایی نام تطبیق داده می‌شود؛ تطبیق حدسی انجام نمی‌شود.
- `/start`، `/help`، `/me`، `/stats`، `/rank` و معادل‌های فارسی پشتیبانی می‌شوند.
- هدف‌ها پیش از نخستین گزارش هم نمایش داده می‌شوند؛ پاداش فعلی با پیش‌بینی پایان ماه تفکیک شده است.
- فایل تکراری مجدداً محاسبه نمی‌شود؛ گزارش روز قدیمی‌تر جای گزارش جدید را نمی‌گیرد.
- ذخیره گزارش و عملکرد همه فروشندگان در یک تراکنش انجام می‌شود.

## حریم خصوصی

این مخزن عمومی است. نام‌ها، اهداف، فروش واقعی، فایل‌های ورودی و توکن‌ها را در Git ثبت نکنید.
داده هدف‌ها جداگانه از مسیر مدیریتی احراز هویت‌شده به D1 وارد می‌شود. فایل‌های آزمون فقط اطلاعات ساختگی دارند.

## اجرای آزمون

Node.js 22.13 یا جدیدتر:

```sh
npm ci
npm test
npm run check:build
```

وابستگی SheetJS از منبع رسمی نسخه 0.20.3 نصب می‌شود؛ package-lock نسخه‌ها را تثبیت می‌کند.

## ادامه استقرار توسط عامل

1. وارد حساب Cloudflare مالک Worker شوید؛ Worker و دیتابیس موجود را بررسی کنید. شناسه D1 در تنظیمات از بسته قبلی بازیابی شده و باید با حساب تطبیق داده شود.
2. Queue با نام `rekord-mehr-imports` باید موجود باشد. اجرای همزمان consumer برابر 1 است؛ این تنظیم برای ترتیب گزارش‌ها ضروری است.
3. رازهای runtime را تنظیم کنید: یکی از `BALE_BOT_TOKEN` / `BALE_TOKEN` / `BOT_TOKEN` (توکن موجود)، `BALE_GROUP_CHAT_ID`، `BALE_ADMIN_IDS` (شناسه‌های عددی جداشده با کاما)، `ADMIN_TOKEN` و `WEBHOOK_SECRET` (مقادیر تصادفی قوی و مستقل).
4. کد را Deploy کنید. با توکن مدیریتی و HTTPS، JSON خصوصی 92 هدف را به `POST /admin/targets` ارسال کنید. کلیدهای JSON: `store,seller,baseline,t20,r20,t30,r30,t40,r40`.
5. `GET /admin/health` را بررسی کنید؛ تعداد هدف‌ها باید 92 باشد.
6. `POST /admin/setup` را با `Authorization: Bearer <ADMIN_TOKEN>` فراخوانی کنید؛ هویت ربات و تطابق Webhook کنترل می‌شوند. این مسیر پیام آزمایشی نمی‌فرستد.
7. از حساب بله کاربر، `/start` و `وضعیت من` و یک SalesReport واقعی مهر را آزمایش کنید. پاسخ، محاسبات و ثبت D1 را با ورودی مقایسه کنید.
8. پس از تأیید استقرار زنده، تغییرات را در main ادغام کنید و نسخه فعال را دوباره بررسی کنید.

مسیر عمومی `/` فقط نسخه سرویس را نمایش می‌دهد. مسیر Webhook دارای راز است. نمایش عمومی جزئیات گزارش، تنظیم عمومی Webhook و مسیر debug حذف شده‌اند.

## حدود بررسی فعلی

13 آزمون محلی با SQLite و فایل‌های ساختگی انجام شده‌اند. فایل واقعی قبلی با 141,240 ردیف نیز بررسی شد: هر 92 فروشنده شناسایی شدند و نتیجه تمام مبالغ با روش مرجع برابر بود. بیشینه حافظه فرایند Node در اجرای مستقل خواننده تدریجی حدود 85MiB بود (در برابر حدود 571MiB روش قبلی). این آزمون‌ها جای تست واقعی Cloudflare و دریافت/ارسال بله را نمی‌گیرند. مصرف حافظه و زمان فایل واقعی بزرگ باید در Worker تأیید شود؛ اگر به سقف منابع حساب برسد، تغییر معماری یا طرح میزبانی نیاز به تصمیم جداگانه دارد.
