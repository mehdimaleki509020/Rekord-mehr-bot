# ربات لیگ غیربرقی آبان ۱۴۰۵

نسخه آبان ربات بله «رکورد غیربرقی مهر» بر بستر Cloudflare Workers + D1
اجرا می‌شود. فایل‌ها و جدول‌های پایگاه داده طرح مهر حذف نمی‌شوند.
فایل‌های `worker.js` و `processor.py` نسخه قبلی هستند و فایل‌های فعال
آبان `worker_aban.js` و `processor_aban.py` هستند.

## قوانین قطعی آبان

تمام مبالغ محاسباتی به **میلیون تومان** هستند.

- تارگت فروشنده = `max(500, 1.2 × فروش فردی مهر)`.
- اگر فروش آبان فروشنده به تارگت برسد، جایزه = `1% × کل فروش آبان`؛ وگرنه صفر.
- فرد بدون فروش مهر (از جمله تازه‌واردها) تارگت ۵۰۰ میلیون تومانی دارد.
- حداقل تارگت سوپروایزر = **کل فروش غیربرقی شعبه در مهر**.
- فقط وقتی کل فروش غیربرقی شعبه در آبان حداقل به فروش مهر رسیده باشد، جایزه سوپروایزر
  = `30% × مجموع جایزه فروشندگان واجد شرایط همان شعبه`؛ در غیر این صورت صفر.
- فروش‌های بدون مشاور نیز در رقم کل شعبه لحاظ می‌شوند ولی جایزه فردی ندارند.
- جایزه نمایش‌داده‌شده تا پایان ماه موقت است.

## نمایش ربات

- فروشنده: فقط «تارگت آبان / فروش تا تاریخ / جایزه».
- سوپروایزر: «حداقل تارگت شعبه / فروش تا تاریخ / جایزه سوپروایزر» و سپس
  نام همه فروشندگان شعبه با سه رقم «تارگت / فروش / جایزه».
- مدیر طرح: ارسال «شبکه» برای مشاهده فروش کل آبان و فهرست همه فروشگاه‌ها
  از بیشترین تا کمترین فروش؛ ارسال نام هر فروشگاه برای دریافت عین گزارش سوپروایزر.
- هر نفر با `/start` یا «وضعیت من» گزارشش را می‌بیند.
- ثبت نام ساده: `ثبت نام نام خانوادگی`؛ برای همنام‌ها
  `ثبت نام نام کامل | نام فروشگاه`.
- اتصال کاربران ثبت‌نام‌کرده مهر به داده آبان، در صورت تطبیق نام و شعبه، خودکار انجام می‌شود.
- سوپروایزرهای قبلی در پایگاه داده باقی می‌مانند. مدیر می‌تواند با Reply روی پیام فرد
  دستور `ثبت سرپرست نام فروشگاه` را اجرا کند.

## بارگذاری روزانه داده‌ها

مدیر طرح فایل کامل و تجمیعی `SalesReport.xlsb` را در چت خصوصی ربات ارسال می‌کند.
**گزارش باید فروش آبان از روز ۱ تا روز گزارش را در بر داشته باشد.**
فایل می‌تواند فقط شامل آبان باشد؛ در این حالت ربات مبنای کامل مهر را از آخرین
گزارش موفق قبلی حفظ می‌کند. برای شروع در پایگاه داده خالی، یک‌بار گزارش شامل
فروش کامل مهر و آبان لازم است. ارسال فقط تراکنش‌های همان روز مجاز نیست.
مطمئن شوید نام فروشگاه، مشاور، سال، ماه، روز، PH11 و مبلغ در فایل ثبت شده‌اند.

ربات فایل را صف می‌کند؛ GitHub Actions هر پنج دقیقه صف را بررسی و فایل را
با `processor_aban.py` پردازش می‌کند. هر بار، فروش تجمعی آبان جایگزین
تصویر قبلی می‌شود و مبنای مهر حفظ می‌شود (فروش روزانه **جمع نمی‌شود** تا دوباره‌شماری رخ ندهد).
اگر گزارش روز قدیمی‌تری از آخرین گزارش باشد، رد می‌شود.

## استقرار و تنظیمات

- Worker: `rekord-mehr-bot.mehdimaleki509020.workers.dev`.
- Cloudflare: D1 با binding به نام `DB`؛ توکن بله در Secret با
  یکی از نام‌های `BALE_TOKEN`، `BALE_BOT_TOKEN`، `BOT_TOKEN`.
- GitHub Actions: دسترسی OIDC برای پردازش گزارش، و
  `CLOUDFLARE_API_TOKEN` و `CLOUDFLARE_ACCOUNT_ID` برای استقرار.
- `/setup`: تنظیم Webhook پس از Deploy (در گردش‌کار انتشار اجرا می‌شود).
- `/debug`: وضعیت Webhook و شمار افراد/شعب/ثبت‌نام‌ها.
- مسیرهای `/processor/*` فقط با توکن OIDC امضاشده گردش‌کار اصلی قابل استفاده‌اند.
